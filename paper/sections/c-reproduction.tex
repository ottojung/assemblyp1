\section{Reproducing the results}
\label{app:reproduction}

The build and proof index are maintained alongside the paper:
\texttt{paper/README.md} gives the TeX build instructions and
\path{docs/verification.md} maps claims to full Lean declarations,
hypotheses and independent scripts.

From the repository root the reproducible paper build is
\begin{verbatim}
sh paper/build.sh
\end{verbatim}
This uses the packages specified in \texttt{paper/manifest.scm} and
runs \texttt{latexmk} with \texttt{biber}. The repository's
\texttt{paper/README.md} describes an alternative Guix-shell build
and the verification workflow.

The unconditional population-uniqueness theorem and its distinction
from the earlier conditional Eulerian-obstruction interface are
explicitly indexed in \path{docs/verification.md}.
That file also distinguishes finite computations from kernel-checked
results and historical source premises.

\noindent\textbf{Lean:} \texttt{\AssemblyLeanToolchain}

\noindent\textbf{Mathlib commit:}\\
\texttt{\AssemblyMathlibRevision}
\end{quote}
The source repository is
\url{https://github.com/ottojung/assemblyp1};
the dependency pin is in \texttt{lake-manifest.json}.
The matching \texttt{docs/verification.md} and the complete
Lean source are included in the tagged repository tree, rather than
living only behind a moving PDF link.

GitHub's CI builds every theorem module with
\texttt{lake build --wfail}, replays the entire library through the
Lean kernel (using \texttt{leanchecker}), and performs an axiom audit.
The accepted logical dependencies are Lean's usual
\texttt{propext}, \texttt{Classical.choice}, and \texttt{Quot.sound};
the audit checks that no additional axioms are introduced.
A verified Lean theorem is evidence for its \emph{stated type};
historical source-to-model correspondence and the paper-level
BEST double-counting argument are not promoted to Lean theorems.
